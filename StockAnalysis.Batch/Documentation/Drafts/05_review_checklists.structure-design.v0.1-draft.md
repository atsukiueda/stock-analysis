# Structure Design — 05_review_checklists.md

> **Draft — not released.** This is a structure proposal for a review-checklist guide/template set.

| Field | Value |
|---|---|
| Proposed artifact | `05_review_checklists.md` |
| Proposed class | Guide with reusable checklist templates |
| Governing documents | Project Constitution; Documentation Governance; relevant domain controls |

## Responsibility

Provide reusable defect-finding prompts for independent reviewers. The artifact supports review judgment; it does not replace reviewer independence, approve work, establish mandatory acceptance thresholds, or define a release procedure.

## Proposed sections

| Section | Responsibility |
|---|---|
| Review purpose and boundary | Review finds defects; author self-check is not independent review |
| Checklist use | Explain scope selection, evidence-based findings, and documented dispositions |
| Universal checklist | Authority, scope, evidence, traceability, lifecycle status, contradictions, maintainability |
| Documentation checklist | Canonicality, terminology, links, classification, migration boundary |
| Governance and policy checklist | Authority, Policy/Standard/Procedure separation, role and decision consistency |
| Workflow and procedure checklist | Handoffs, role separation, exception route, delegated mechanics |
| Model and decision-system checklist | Upstream knowledge, validation boundary, explainability, investment separation, monitoring links |
| Development checklist | Architecture dependency, domain boundaries, validation and traceability routing |
| Finding format | Severity, evidence, affected scope, recommendation, disposition link |
| Maintenance | Checklist evolution and domain-specific extension boundary |

## Explicit exclusions

The artifact will not define approval authority, reviewer counts, thresholds, scoring, model metrics, test methods, coding rules, or release commands. These belong to applicable Standards or Procedures.
